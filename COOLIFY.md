# Activepieces Community on Coolify

This deployment uses the official `0.92.1` image with one app, one worker,
PostgreSQL and persistent Redis. Deployment configuration is tracked on
`deploy/coolify`; `main` follows upstream.

In Coolify, use Docker Compose with `/docker-compose.coolify.yml` and assign
the public HTTPS domain to the `app` service on port 80.

Set these runtime variables in Coolify:

| Variable | Value |
| --- | --- |
| `AP_FRONTEND_URL` | Public HTTPS URL |
| `AP_ENCRYPTION_KEY` | 16 random bytes encoded as 32 hex characters |
| `AP_JWT_SECRET` | 32 random bytes encoded as hex |
| `AP_POSTGRES_PASSWORD` | Random database password |
| `AP_REDIS_PASSWORD` | Random Redis password |
| `AP_WORKER_TOKEN` | Worker JWT signed with `AP_JWT_SECRET`, generated by `npx @activepieces/cli workers token` |

The first account created becomes the administrator. Subsequent users require
an invitation. Configure AI provider keys and Facebook Pages connections in the UI.

Verify all four containers are healthy, open the UI, and check
`GET /api/v1/health`. The worker connects internally at `http://app`.

Before upgrading, back up PostgreSQL, Redis and the environment secrets,
especially `AP_ENCRYPTION_KEY`. Redeploys preserve named volumes. To recover a
failed upgrade, restore its matching database backup and redeploy the previous
Git commit/image; changing only the image may not undo database migrations.
Never remove the volumes during rollback.
